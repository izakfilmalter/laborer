## Issue 2: Schema: no-op legacy materializers and remove deprecated columns

**Status:** done

### Changes made

1. **Removed deprecated columns from `panelLayout` table** (`packages/shared/src/schema.ts`):
   - Removed `layoutTree` (json, `PanelNodeSchema`)
   - Removed `activePaneId` (text, nullable)
   - Removed `workspaceOrder` (json, array of strings)
   - Table now has only: `windowId` (primary key), `windowLayout`, `activeWindowTabId`

2. **Made legacy event materializers no-ops** (`packages/shared/src/schema.ts`):
   - `v1.LayoutSplit` → `() => []`
   - `v1.LayoutPaneClosed` → `() => []`
   - `v1.LayoutPaneAssigned` → `() => []`
   - `v1.LayoutRestored` → `() => []`
   - `v1.LayoutWorkspacesReordered` → `() => []`
   - Follows the same pattern used for deprecated terminal events (Issue #145)

3. **Legacy event definitions retained** — event schemas (`layoutEventSchema`, etc.) remain
   in the schema so old events in the eventlog still have valid definitions.

4. **Hierarchical event materializers unchanged** — all `windowLayout*`, `windowTab*`,
   `panelTab*` materializers correctly upsert `{ windowId, windowLayout, activeWindowTabId }`.

5. **Updated `schema.test.ts`** (`packages/shared/test/schema.test.ts`):
   - Rewrote legacy materialization tests to verify no-op behavior (table stays empty)
   - Removed assertions on `layoutTree`, `activePaneId`, `workspaceOrder` from hierarchical event tests
   - Replaced coexistence tests with a single test verifying legacy events don't affect hierarchical columns
   - All 71 tests in packages/shared pass

### Known downstream impact

Removing the columns causes TypeScript errors in consumer code that reads these fields
from `panelLayout` query results. These are expected and will be resolved by subsequent issues:
- Issue 3: handleSetActivePaneId (reads `activePaneId`)
- Issue 12: Seeding/reconciliation (reads `layoutTree`, `activePaneId`, `workspaceOrder`)
- Issue 10: index.tsx consumers (reads derived values)

## Issue 3: handleSetActivePaneId uses hierarchical focus only

**Status:** done

1. **Rewrote `handleSetActivePaneId`** (`apps/web/src/routes/-hooks/use-panel-layout.ts`):
   - Removed `layoutPaneAssigned` event commit entirely
   - Now uses `saveFocusedPaneId()` on the hierarchical `WindowLayout` and commits `windowLayoutPaneAssigned`
   - Validates pane ID against the hierarchical tree via `resolveActivePaneForWindowTab` when null is passed
   - No longer depends on `layout`, `persistedLayoutTree`, or `defaultLayout`

2. **Derived `persistedActivePaneId` from hierarchical tree**:
   - Primary path: `resolveActivePaneForWindowTab(activeTab)` walks the hierarchy (active window tab > workspace tile leaves > active panel tab > focusedPaneId)
   - Fallback: `ensureValidActivePaneId(layout, null)` for cases where hierarchical resolution returns no result (e.g., empty migrated layout with no workspace tiles)

3. **Derived `activeWorkspaceId` from hierarchical tree**:
   - Added `resolveActiveWorkspaceForWindowTab()` to `window-tab-utils.ts`
   - Walks workspace tile leaves to find which workspace contains the focused pane
   - Returned from `usePanelLayout()` hook, consumed directly in `index.tsx`
   - Removed `findNodeById(layout, activePaneId)` derivation from `index.tsx`

4. **Removed `layoutPaneAssigned` from all focus-restoration callbacks**:
   - `commitWindowTabSwitchWithFocus`: Simplified to just `commitWindowLayout(windowTabSwitched, newLayout)` — hierarchical focusedPaneId is sufficient
   - `commitPanelTabSwitchWithFocus`: Simplified to just `commitPanelTabLayout(panelTabSwitched, newLayout)`
   - `handleCloseWindowTab`: Removed legacy tree derivation and `layoutPaneAssigned` commit after tab close
   - `handleAssignTerminalToPane` step 3: Replaced `layoutPaneAssigned` with `saveFocusedPaneId` + `windowLayoutPaneAssigned`

5. **Replaced `layoutPaneAssigned` in `commitAssignment` helper**:
   - Removed the dual-write pattern (legacy event + sync to hierarchical)
   - Now: sync legacy tree to hierarchical, save focus, commit single `windowLayoutPaneAssigned`

6. **Replaced `layoutPaneAssigned` in `handleToggleDevServerPane`**:
   - Extracted `commitDevServerSync` and `spawnAndAssignDevServer` helpers to reduce complexity
   - All dev server toggle paths now sync to hierarchical tree and commit `windowLayoutPaneAssigned`

7. **Hardcoded `rawPersistedActivePaneId` and `persistedWorkspaceOrder` to null**:
   - These legacy columns were removed from the schema in Issue 2
   - Code still references them for backward-compatible migration paths but always reads null

8. **Import changes**:
   - Added `windowLayoutPaneAssigned` import from `@laborer/shared/schema`
   - Removed `layoutPaneAssigned` import (no longer committed anywhere)
   - Added `resolveActiveWorkspaceForWindowTab` import from `window-tab-utils`

9. **Updated tests** (`apps/web/test/use-panel-layout.test.ts`):

## Issue 4: handleSplitPane operates on hierarchical tree

**Status:** done

### Changes made

1. **Rewrote `handleSplitPane`** (`apps/web/src/routes/-hooks/use-panel-layout.ts`):
   - No longer reads from `persistedLayoutTree` or `defaultLayout` (legacy `PanelNode` tree)
   - No longer calls `splitPane()` from `layout-utils.ts` (legacy)
   - No longer calls `syncLegacyTreeToHierarchical()` to bridge legacy → hierarchical
   - No longer commits `layoutSplit` (legacy event, now a no-op)
   - Now operates directly on `persistedWindowLayout` (hierarchical `WindowLayout`)
   - Uses `findWorkspaceForPane()` (new helper) to locate the workspace containing the target pane
   - Uses `updateWorkspaceTileLeaf()` + `splitPaneInPanelTree()` to split the active panel tab's tree

2. **Added `findWorkspaceForPane` helper** (`use-panel-layout.ts`):

## Issue 5: handleClosePane operates on hierarchical tree

**Status:** done

### Changes made

1. **Rewrote `handleClosePane`** (`apps/web/src/routes/-hooks/use-panel-layout.ts`):
   - No longer reads from `persistedLayoutTree` or `defaultLayout` (legacy `PanelNode` tree)
   - No longer calls `closePane()` from `layout-utils.ts` (legacy)
   - No longer calls `findSiblingPaneId()` from `layout-utils.ts` (legacy)
   - No longer calls `getTerminalIdsToRemove()` from `layout-utils.ts` (legacy)
   - No longer calls `findNodeById()` from `layout-utils.ts` (legacy)
   - No longer calls `ensureValidActivePaneId()` from `layout-utils.ts` (legacy)
   - No longer calls `syncLegacyTreeToHierarchical()` to bridge legacy → hierarchical
   - No longer commits `layoutPaneClosed` (legacy event, now a no-op)
   - Now operates directly on `persistedWindowLayout` (hierarchical `WindowLayout`)
   - Uses `findWorkspaceForPane()` to locate the workspace containing the target pane
   - Uses `updateWorkspaceTileLeaf()` + `closePaneInPanelTree()` to close the pane in the active panel tab
   - Uses `findPanelTreeLeaf()` to find the closing leaf and extract its terminal ID
   - Uses `findSiblingPaneIdInPanelTree()` to compute focus transfer target before closing
   - Uses `saveFocusedPaneId()` to transfer focus to the sibling pane
   - Commits `windowLayoutPaneClosed` (hierarchical event) instead of `layoutPaneClosed`

2. **All-panes-closed edge case**:
   - When `closePaneInPanelTree` returns `undefined` (all panes removed), creates an empty
     `PanelLeafNode` placeholder so the panel tab shows the empty state CTA
   - No longer commits a legacy `LeafNode` placeholder or resets `hasSeeded`

3. **Terminal cleanup**:
   - Extracts terminal ID from the `PanelLeafNode` in the hierarchical tree
   - Calls `removeTerminalOptimistically()` after the tree mutation (same effect, cleaner ordering)

4. **Import changes**:
   - Added `windowLayoutPaneClosed` import from `@laborer/shared/schema`
   - Added `closePaneInPanelTree`, `findSiblingPaneIdInPanelTree` imports from `window-tab-utils`
