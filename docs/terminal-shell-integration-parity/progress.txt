## Issue 1: Positional metadata on commands (OSC 633;A + 633;C) — COMPLETED

### Summary
Added OSC 633;A (prompt start) and 633;C (command executed) handlers to the
headless terminal's shell integration, and enhanced 633;B and 633;D to track
positional metadata via xterm buffer positions. Serialized commands now include
`promptStartLine`, `startLine`, `executedLine`, `endLine`, `startX`, `executedX`,
and `commandStartLineContent` fields populated from live command tracking.

### Changes
- `packages/terminal/src/lib/headless-terminal.ts`:
  - Added `getBufferLineContent()` and `getAbsoluteCursorLine()` helpers
  - Added OSC 633;A handler: records prompt start line in `pendingPromptStartLine`
  - Enhanced OSC 633;B handler: registers cursor line as `startLine`, captures
    `startX` from `cursorX`, captures `commandStartLineContent` from buffer,
    consumes `pendingPromptStartLine` as `promptStartLine`
  - Added OSC 633;C handler: records `executedLine` and `executedX` on in-flight command
  - Enhanced OSC 633;D handler: records `endLine` from cursor position, pushes
    completed command with all positional fields
  - Extended `InFlightCommand` interface with positional fields
  - Added `pendingPromptStartLine` to `HeadlessCommandState`
  - Updated `serializeCurrentCommand()` to include positional metadata for in-flight commands
  - Extracted `handleCommandFinished()` and `handlePropertySequence()` helper
    functions to keep complexity under Biome's limit

- `packages/terminal/test/headless-terminal.test.ts`:
  - Updated 5 existing tests to expect positional metadata fields
  - Added 7 new tests:
    - Full A->B->E->C->D lifecycle with positional ordering assertions
    - `commandStartLineContent` capture from buffer at 633;B
    - `startX` from cursor position at 633;B
    - Multiple commands with ordering assertions
    - 633;B without preceding 633;A (promptStartLine undefined)
    - 633;D without preceding 633;C (executedLine/executedX undefined)
    - In-flight command after A->B includes positional metadata but not endLine

- `packages/terminal/test/terminal-session-persistence.test.ts`:
  - Updated 1 test to expect positional metadata in persisted state

### Verification
- TypeScript: `npx tsc --noEmit` passes with 0 errors
- Biome: `bunx biome check` passes on all modified files
- Tests: 25/25 headless-terminal tests pass, 32/32 persistence tests pass
- Data channel tests: pre-existing flaky failures confirmed unchanged
- Terminal-manager tests: pre-existing infrastructure failure confirmed unchanged

## Issue 5: Capability store + CwdDetection — COMPLETED

### Summary
Created the capability store infrastructure and implemented CwdDetection as the
first capability. The capability store tracks per-terminal capabilities that are
serializable alongside command detection. CwdDetection is fed by four OSC sources:
OSC 633;P Cwd (VS Code), OSC 7 (standard file:// URI), OSC 9 (Windows-friendly),
and OSC 1337 CurrentDir (iTerm2). Capabilities flow through all layers: headless
terminal tracking, persistence serialization, data channel replay, and the
terminal manager.

### Changes
- `packages/terminal/src/services/terminal-session-persistence.ts`:
  - Added `SerializedCwdDetectionEntry`, `SerializedCwdDetection`, and
    `SerializedCapabilityStore` types
  - Added optional `capabilities` field to `SerializedReplayEvent`
  - Updated `ReplayRecorder` to track and roundtrip `capabilities`
  - Updated `serializeState()` to accept and persist `getCapabilityState` getter
  - Exported all new types

- `packages/terminal/src/lib/headless-terminal.ts`:
  - Added `CwdDetectionState` interface for per-terminal cwd tracking
  - Added `cwdDetection` field to `HeadlessCommandState`
  - Added `recordCwdChange()` helper that feeds both legacy `commandState.cwd`
    and the new `cwdDetection` capability state
  - Added `parseFileUri()` helper for OSC 7 file:// URI parsing with
    percent-decoding
  - Updated OSC 633;P Cwd handler to use `recordCwdChange()` instead of
    direct assignment
  - Added OSC 7 handler: parses file:// URIs and feeds CwdDetection
  - Added OSC 9 handler: parses Windows sub-command 9 format and feeds CwdDetection
  - Added OSC 1337 handler: parses CurrentDir= payload and feeds CwdDetection
  - Added `getCapabilityState()` method to `HeadlessTerminalManager` interface
    and implementation, which serializes the cwd detection state

- `packages/terminal/src/services/terminal-data-channel.ts`:
  - Updated `encodeReplay()` to include `capabilities` field in JSON payload

- `packages/terminal/src/services/terminal-manager.ts`:
  - Added `getCapabilityState()` to the `TerminalManager` interface
  - Wired through to `headlessManager.getCapabilityState()` in implementation

- `packages/terminal/src/utility-main.ts`:
  - Updated `serializeState()` call to pass `getCapabilityState` getter

- `packages/terminal/test/headless-terminal.test.ts`:
  - Added 13 new tests:
    - CwdDetection from OSC 633;P Cwd
    - CwdDetection from OSC 7 with hostname
    - CwdDetection from OSC 7 with empty hostname
    - CwdDetection from OSC 7 with percent-encoded characters
    - CwdDetection from OSC 9;9 (Windows)
    - CwdDetection from OSC 1337 CurrentDir
    - Cwd history across multiple changes from different sources
    - Cwd detection feeding into command cwd field
    - Returns undefined when no cwd detected
    - Returns undefined for non-existent terminal
    - Ignores OSC 7 with non-file URI
    - Ignores OSC 9 without sub-command 9 prefix
    - Ignores OSC 1337 with non-CurrentDir payload

- `packages/terminal/test/terminal-session-persistence.test.ts`:
  - Added 4 new tests:
    - Serializes live capability state from headless terminal cwd detection
    - Preserves restored capability state when serializing again
    - Serializes cwd detection from multiple OSC sources
    - Omits capabilities when no capability state exists
