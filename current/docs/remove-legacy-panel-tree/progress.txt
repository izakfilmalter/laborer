## Issue 7: Mutation handlers operate on WindowLayout directly — DONE

**Date:** 2026-03-26

### What was done

1. Rewrote all mutation handlers in `use-panel-layout.ts` to operate directly on `WindowLayout` instead of through the legacy flat `PanelNode` tree with `syncLegacyTreeToHierarchical` bridge:
   - **`handleSplitPane`**: Walks all workspace tile leaves to find the pane, calls `splitPaneInTree` on the active panel tab's `PanelNode`, updates focus to the new pane, commits `windowLayoutUpdated` with `reason: 'split'`.
   - **`handleClosePane`**: Uses extracted `closePaneInLayout` helper that finds the pane across workspaces, closes it with `closePaneInTree`, transfers focus to sibling via `findSiblingPaneId`. Removes the panel tab entirely if it was the last pane. Detects empty layouts and resets for re-seeding.
   - **`handleAssignTerminalToPane`**: Uses extracted `navigateToTerminal` for existing terminals, `ensureWorkspaceInActiveTab` to ensure workspace presence, and `assignTerminalInWorkspace` for the actual assignment (handles direct pane assignment, empty pane reuse, and auto-split).
   - **`handleCloseWorkspace`**: Walks hierarchical tree to collect terminal IDs from workspace tile leaves instead of using `getWorkspaceTerminalIds` on the legacy tree.
   - **`handleCloseTerminalPane`**: Removed legacy fast-path. Uses `closeTerminalInWindowLayout` as the sole search path across all panel tabs.
   - **`handleToggleDevServerPane`**: Completely rewritten to create/remove `devServerTerminal` panel tabs instead of toggling `devServerOpen`/`devServerTerminalId` sidebar flags on leaf nodes. Uses `findWorkspaceForPane` to locate the workspace, `addPanelTab` to create, and `removePanelTab` to remove.
   - **`handleResizePane`**: Walks workspace tile leaves to find the active panel tab containing the pane, then calls `computeResize` on that panel tab's tree.
2. Deleted `syncLegacyTreeToHierarchical` function (65 lines) — the bridge between legacy and hierarchical trees is no longer needed.
3. Deleted `commitAssignment` helper — replaced by inline `assignTerminalInWorkspace` pure function.
4. Deleted `commitDevServerUpdate` helper — replaced by panel tab operations.
5. Deleted `DEFAULT_NEW_WINDOW_LAYOUT` constant — seeding now uses `initialLayout` directly.
6. Removed `persistedLayoutTree` (always `undefined` after DB nuke), `persistedLayoutRepair`, `persistedWorkspaceOrder` (always `null`).
7. Removed `defaultLayout` (was `nativeWindowId ? DEFAULT_NEW_WINDOW_LAYOUT : initialLayout`) — simplified to use `initialLayout` directly.
8. Removed imports of `convertPanelTree`, `migrateToWindowLayout`, `filterTreeByWorkspace` from `layout-migration.ts`.
9. Removed imports of `closePane`, `splitPane`, `computeTerminalPaneAssignment`, `findLeafByTerminalId`, `getTerminalIdsToRemove`, `getWorkspaceTerminalIds`, `replaceNode`, `getStaleTerminalLeaves`, `findNewLeafAfterSplit` from `layout-utils.ts`. Only `findNodeById`, `getLeafIds`, `getLeafNodes` remain (used by the derived `layout` for Issue 8 consumers).
10. Added imports from `panel-tree-utils.ts`: `closePaneInTree`, `findLeaf`, `findSiblingPaneId`, `getPanelTreeLeafIds`, `splitPaneInTree`, `NavigationDirection` type.
11. Added import of `getAllWorkspaceTileLeaves` from `window-layout-utils.ts`.
12. Extracted 5 pure helper functions at module level to reduce cognitive complexity below lint threshold (max 20):
    - `closePaneInLayout` — finds and closes a pane across all workspace tile leaves
    - `navigateToTerminal` — switches to the tab/panel tab containing a terminal
    - `findWorkspaceForPane` — locates the workspace tile leaf containing a pane
    - `ensureWorkspaceInActiveTab` — ensures a workspace exists in the active window tab
    - `assignTerminalInWorkspace` — assigns a terminal to a workspace's active panel tab (handles direct, empty, and split cases)
    - `findEmptyTerminalPaneInTree` — finds an unoccupied terminal pane in a panel tree
13. Kept `deriveLegacyTreeFromHierarchical` for the `layout` derivation — consumers (`PanelHotkeys`, `PanelContent`, `WorkspaceFrames`, `index.tsx`) still depend on the flat tree. Will be ported in Issue 8.
14. Kept `layout-utils.ts` imports for `findNodeById`, `getLeafIds`, `getLeafNodes` — used by the derived `layout` value passed to consumers. Will be removed in Issue 8.
15. `bun run check` passes (typecheck + format + all 1270 web tests, all packages pass).

## Issue 4: Replace repair code with Effect Schema decode — DONE

**Date:** 2026-03-26

### What was done

1. Created `decodeWindowLayout` function in `window-layout-utils.ts` — a Schema-based replacement for the ~490-line manual `repairWindowLayout` function and its 12+ helper functions.
2. The new function uses a two-phase approach:
   - **Phase 1 (fast path):** `Schema.decodeUnknownEither(WindowLayoutSchema)` for strict validation. Valid layouts hit this path and skip all manual validation. Post-decode repair transforms handle edge cases like single-child split collapse, size redistribution, stale active ID resolution, and empty ID filtering.
   - **Phase 2 (lenient fallback):** When strict Schema decode fails (malformed data), a lenient decode pipeline processes the input field-by-field. It tries `Schema.decodeUnknownEither` at each node level (WindowTab, PanelTab, PanelNode, WorkspaceTileNode), falling back to manual field validation only when Schema decode fails at that level. Invalid nodes are dropped, valid ones are preserved.
3. Deleted the old `repairWindowLayout` function and all 14 helper functions (~490 lines removed):
   - `VALID_PANE_TYPES`, `VALID_DIRECTIONS`, `isRecord` (old copy), `repairSplitSizes`, `repairPanelNode`, `repairLeafNode`, `repairSplitNode`, `repairPanelTab`, `repairWorkspaceTileNode`, `repairPanelTabsArray`, `resolveActivePanelTabId`, `repairWorkspaceTileLeaf`, `repairTileSplitChildren`, `repairWorkspaceTileSplit`, `repairWindowTab`, `repairWindowLayout`.
4. Added Effect Schema imports: `PanelNodeSchema`, `PanelTabSchema`, `WindowLayoutSchema`, `WindowTabSchema`, `WorkspaceTileNodeSchema`, plus `Either` and `Schema` from `effect`.
5. Module-level cached Schema decoders for performance: `decodeWindowTab`, `decodePanelNode`, `decodePanelTab`, `decodeTileNode`.
6. Shared repair transform functions used by both fast and lenient paths: `repairTransforms`, `repairWindowTabTransform`, `repairWorkspaceTileTransform`, `repairPanelTabTransform`, `repairPanelNodeTransform`, `repairSizesTransform`, `resolveActiveTabId`, `resolveActiveId`, `deepEqual`.
7. Replaced the call site in `use-panel-layout.ts`: `repairWindowLayout(raw)` → `decodeWindowLayout(raw)`. Updated import from `repairWindowLayout` to `decodeWindowLayout`.
8. Wrote 15 TDD tests for `decodeWindowLayout` in `hierarchical-persistence.test.ts` covering all edge cases from the old `repairWindowLayout` tests:
   - Valid layout round-trip (no repair needed)
   - Non-object input returns undefined
   - Missing/invalid tabs returns undefined
   - All tabs invalid returns empty layout
   - Stale activeTabId resolved to first valid tab
   - Invalid window tabs (empty id) dropped
   - Invalid panel tabs dropped
   - Stale activePanelTabId resolved
   - Single-child workspace tile splits collapsed
   - Single-child panel split nodes collapsed
   - Invalid pane types cause panel tab to be dropped
   - Invalid optional fields stripped (non-string terminalId)
   - Invalid sizes redistributed as equal
   - Deeply nested hierarchies handled
9. Deleted the old 15 `repairWindowLayout` tests — replaced by the equivalent `decodeWindowLayout` tests.
10. Removed `repairWindowLayout` from the export list.
11. `bun run check` passes (typecheck + format + all tests across all packages).

### Notes

- The `RepairWindowLayoutResult` interface is preserved with the same shape (`{ wasRepaired: boolean; windowLayout: WindowLayout | undefined }`) for backward compatibility with the call site.
- The `isRecord` type guard is kept (single definition) since it's used by the lenient decode pipeline.
- The lenient decode pipeline is structurally similar to the old manual repair code but is significantly more concise because it delegates to Schema decode at each level first, only falling back to manual checks when Schema fails.
